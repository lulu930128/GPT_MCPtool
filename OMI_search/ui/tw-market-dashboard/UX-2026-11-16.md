# 交易工作台 v4 UX 健檢與改版

範圍：React、CSS、前端測試與既有 CC 的 OMI_search 更新。保留原深色 palette、字體、交易契約、單一確認 modal、原位撤單與 UNKNOWN latch。不修改 Backend／Native，不呼叫真實送／撤／改單，不 commit／push。

## 診斷與本輪處理

實際讀取原始元件、既有 WIP、390px iframe 截圖，再檢查改版後 375／390／650／1280px DOM 與截圖。正式 MCP opener 可用，但 CUA 回報 Browser Host unavailable，正式 Host 的畫面未驗證。

- 原 `.workspace-order-card` 是透明背景、零圓角、單一頂線，與內部診斷線相同。改為有間隔、背景、邊框及側邊標記的獨立委託卡；技術摘要／診斷改用次要 disclosure，預設收合。
- 一般表單與委託卡只接收 symbol。新增共用的 UI 名稱快取，僅呼叫既有 `omi_search_tw_symbols`；驗證 query 與唯一 exact stock_id，成功五分鐘、失敗十五秒過期，並提供手動重查。查詢失敗保留代碼、明示名稱未取得；不影響交易操作。切股／換 bridge 丟棄舊結果，美股不查台股主檔。沒有第二套股票資料來源、持久化 store 或新 API。
- 修改／刪除／送單同尺寸擠在一起。送單為原位主動作；修改／刪除收進原卡的次要操作，編輯仍原位。研究管理收合，加入待送單優先。停損停利表單收合但標明是否啟用。
- 本地已送來源與券商回報重複。僅在既有 stageNativeReview 驗證後，再比對 execution、帳戶、日期、券商編號、symbol 與唯一性，將同筆券商回報收合為關聯入口；原位 BrokerOrderControls 與 latch 保留。不同 execution、身分衝突、外部單都保留獨立卡片。82.5／800 與 83.1／1000 的兩筆 3702 fixture 不合併。
- 首屏保留股票名稱、方向／狀態、限價／股數、成交與可得的券商剩餘回報。剩餘量僅取當次 fact，不用不完整成交自行相減。Native 回讀狀態、原始 source／receipt 仍保存在可展開診斷。
- 主操作與表單控制至少 44px，次要按鈕有間隔，數字採 tabular figures，保留 focus-visible；不引入動態效果或外部字型。

使用已安裝的 `ui-ux-pro-max` 和 `redesign-skill`，實跑 `search.py --design-system`。採用其層級、漸進揭露、可觸控與可存取性原則。搜尋建議的行銷 funnel／parallax 不適合交易工作台，未採用；依使用者要求保留 palette 和字體。
