# Taiwan Workspace iframe 高度回授修復

日期：2026-10-09。僅修改 OMI_search 前端、回歸測試與文件；保留既有 WIP，未 restart、commit/push、修改 SDK/protocol、backend、PAOS、KGI 或執行交易。

## 原因與證據界限

現場回報為 ChatGPT iframe 黑塊與聊天頁持續向下推。舊 CSS 在寬度 ≥651px、高度 ≥700px 時把側欄設為 `100dvh - 76px`，而 host 可能再用文件高度設定 iframe。當側欄以外的高度超過 76px，回授會增長；高度門檻又會突然啟用此規則。原來樹區 `max-height:min(65dvh,680px)` 也依賴 host 分配的高度。

新增明確標為 mock 的幾何模型：設定外圍高度 128px，從 699px 執行 20 輪；舊規則先跨越門檻，之後每輪增加 52px。新規則在 1440／1150／650／390 寬度、unknown／inline／pip／fullscreen 與返回 inline、不同內容及初始高度 180／699／700／1100／12000 下，一次重新計算後穩定。模型讀取 CSS 實際 pixel bounds，搭配獨立 CSS guard 禁止 viewport-height 單位與高度／aspect-ratio media query。

這證明特定 auto-size 模型下的回授機制，**不是 ChatGPT 實際幾何重現**。實際 host 的量測方式與外圍高度仍未驗證。

bridge 的重複通知則有執行證據：將新測試放到本輪修改前保存的 `bridge.ts`，20 次 resize + 20 次 globals 與 3 個延遲 captures，publication 從 6 增至 49；修正版維持 6。這是可確認的無效 React 更新放大來源，不能單獨解釋尺寸增長。

## 尺寸責任

- 所有 mode，包括 unknown 與 fullscreen 請求尚未被 host 接受時，都用同一套有界高度。沒有使用 `innerHeight` 或 host `maxHeight` 來定義內容高度，也沒有 fullscreen 成功的假設。
- >650px：側欄 820px，搜尋與持股各自最多 25%，群組樹 flex 填滿剩餘空間，三區皆保留捲動存取。fullscreen 保留可用的高側欄，但不宣稱剛好填滿 host viewport。
- ≤650px：側欄自然高度，上方區塊各最多 240px，樹高 400px。大內容仍可在區塊內捲動。
- 側欄不再 sticky；只保留樹內的 sticky heading，短 iframe 可捲到文件底部。移除樹的 overscroll containment，讓捲到邊界後可繼續捲外層。Workspace body 明確 `overflow:visible`，沒有用 hidden/clip 蓋住問題；root gutter 穩定，避免 scrollbar 出現／消失時改變可用寬度。
- 保留 grid 跨列側欄、TAIEX/TPEX 雙卡、360px context、Group 45 直接股票、選取／late-response guards、預設收合的資料揭露、原圖表與 M2 SYNTHETIC。
- bridge 僅在實質欄位改變時發布新物件與 updatedAt；真實尺寸或 mode 變更仍通知。既有 initialize、單次自動 fullscreen、手動 fullscreen、20 秒 timeout 和清理邏輯不變；ResizeObserver 未停用。
