OMI_search Public Tool Boundary
===============================

目的
----

OMI_search 是 OMI 公開能力的 MCP 映射層，不是第二個 AI decision core、market service 或 response formatter。

唯一 upstream contract
----------------------

- Schema：GET /api/ai/tools 中的 omi.ask input_schema
- Execution：POST /api/ai/ask
- Response：omi.decision.v4
- Offline schema：由 OMI generator 產生的 public_contract_snapshot.json

Adapter 可做
----------

1. MCP protocol 與 HTTP transport。
2. canonical arguments 一對一 forwarding。
3. 固定 read-only trust boundary：
   - contract_version=omi.decision.v4
   - caller_profile=omi_search
   - allow_llm=false
   - allow_write=false
4. 明確 compatibility mapping：
   - refresh_if_missing -> allow_external_fetch
   - include_intraday -> market_data_params.include_intraday
   - intraday_limit -> market_data_params.intraday_limit
   - legacy omi.search 的 query -> question
   - legacy omi.search 的 stock_id/symbol -> target
5. 明確 shortcut mapping：tool name + fields -> canonical target/parameters。
6. 驗證 backend response 是 omi.decision.v4，並原樣交付。

Adapter 不可做
------------

1. Question keyword / intent classification。
2. Question rewrite 或 prompt augmentation。
3. Target、market、analysis horizon、freshness 或 refresh inference。
4. 依 US/TW/JP/KR/crypto 等市場條件改變 refresh policy。
5. 自行建立 tool budget、strategy、ranking、limit、selection 或 refresh defaults。
6. Clamp、修正或重解釋 backend-owned values。
7. Response summary、compact projection、live summary、field trimming 或 business status reinterpretation。
8. 直接讀寫 OMI DB、呼叫 provider、執行 LLM、寫入 report/memory。

公開 surface
------------

- omi_ask
- omi_read_market_overview
- omi_read_stock_context
- omi_read_data_freshness
- omi_read_source_health
- omi_read_capability_status

omi.search 是 hidden legacy alias，不得出現在 tools/list。

Schema 投影規則
-------------

Backend schema 是 target/capability/parameter 的 system of record。Adapter 只可以：

- 移除 caller 不可設定的 allow_llm、allow_write、allow_external_fetch、caller_profile。
- 將 mode surface 限制為 data_only、brief、full。
- 加入 refresh_if_missing、include_intraday、intraday_limit、include_raw compatibility fields。

其餘 schema、x-omi metadata 與 digest 必須保留。Live backend 不可用時才使用 generated snapshot。

Request 不變量
-------------

- canonical omi_ask 必須有 question。
- question 的文字與空白不得被 adapter 改寫。
- 沒有 explicit target 時，不得從 stock_id、symbol 或 question 推斷 target。
- 沒有 explicit refresh_if_missing=true 時，allow_external_fetch 必須是 false。
- tool_budget 與所有 backend-owned fields 只在 caller 明確提供時 forwarding，且值不改變。
- shortcuts 固定 mode=data_only，只映射其明確 tool fields。

Response 不變量
--------------

- backend v4 object identity 不做 semantic projection。
- content 與 structuredContent 表達同一份 backend payload。
- TARGET_NOT_FOUND、missing、partial、stale 等 business state 是 transport success。
- HTTP/protocol/serialization/non-v4/internal failure 才是 MCP isError=true。

新增能力流程
----------

1. 先在 OMI backend 定義公開 target/capability/parameter/response contract。
2. 更新 backend tests 與 /api/ai/tools。
3. 用 OMI generator 更新 public_contract_snapshot.json。
4. Adapter 只增加必要的 mechanical forwarding 或 explicit shortcut mapping。
5. 驗證 schema digest、payload identity、MCP protocol 與 live runtime。

任何需要「判斷」的新增需求都應回到 OMI backend，不可先寫進 OMI_search。
